# 1. 서론

## 1.1 문서 목적 및 범위
본 문서는 안전한 사내 협업을 위한 경량 클라우드 파일 공유 시스템인 **'미니 드라이브(Mini Drive)'**에 대한 테스트 수행 계획과 테스트 케이스를 정의하고, 기능적/비기능적 요구사항의 최종 검증 결과를 기록하기 위해 작성되었다. 

본 문서에서는 요구사항 정의서 및 품질 요소 추정서에 명시된 기준을 바탕으로 사용자 인증, 파일/폴더 관리, 권한 기반 공유, 다중 필터 검색, 버전 관리 기능과 함께 성능 및 보안성에 대한 테스트 범위, 테스트 항목, 상세 테스트 케이스 및 검증 결과를 기술한다.

---

## 1.2 프로젝트 개요
본 시스템은 조직 내 여러 팀이 문서를 중앙 집중식으로 보관하고 안전하게 공유할 수 있도록 지원하는 웹 기반 파일 관리 시스템이다. 기존 사내 업무 환경에서 메신저나 이메일 공유 시 발생하던 버전 파편화, 파일 검색 지연, 외부 유출 위험을 해결하는 것을 목적으로 한다. 

불필요하게 무거운 기능을 배제한 '경량화(Lean & Fast)' 아키텍처를 채택하여, 직관적인 UI/UX를 제공함으로써 사용자의 학습 비용을 최소화하고 서버 인프라 자원을 최적화하여 고효율 협업 환경을 보장한다.

---

## 1.3 용어 정의

| 용어 | 설명 |
| :--- | :--- |
| **사용자** | 시스템에 계정을 가지고 파일을 보관, 검색, 공유하는 사내 일반 임직원 |
| **관리자** | 전체 시스템 제어 및 계정 생성/삭제, 사용자별 저장 공간(Quota)을 할당하는 주체 |
| **업로드** | 클라이언트 장치 내 로컬 파일을 서버 스토리지 엔진의 지정 경로에 안전하게 저장하는 기능 |
| **다운로드** | 서버 스토리지에 보관된 파일을 사용자의 로컬 장치로 손실 없이 전송받는 기능 |
| **공유** | 외부 협력업체 및 내부 팀원에게 파일 권한(조회/수정/댓글)을 세분화하여 접근을 허용하는 기능 |
| **Quota** | 시스템 관리자가 개별 사용자에게 할당한 데이터 최대 저장 공간 한도 제한치 |
| **낙관적 락** | 동시 수정 충돌을 방지하기 위해 데이터 갱신 시 버전(Version) 정보를 비교하여 제어하는 방식 |
| **만료 링크** | 보안 강화를 위해 사외 협력업체 공유 시 설정된 유효 시간이 지나면 다운로드가 차단되는 URL |

# 2. 테스트 개요

## 2.1 테스트 범위
본 테스트는 시스템 내부 구현 논리보다는 명세 구조와 사용자 흐름을 검증하는 블랙박스 테스트(Black-box Testing)를 기반으로 수행하며, 시스템 전 계층(Full-Stack)을 대상으로 한다.

| 범위 | 내용 |
| :--- | :--- |
| **사용자 기능** | 이메일 포맷 유효성 검증, 비밀번호 제약 사항, 로그인 세션 인증 성공 및 실패 흐름 검증 |
| **파일 관리** | 표준 포맷 업/다운로드, 특수문자 제한, 드래그 앤 드롭 이동, 휴지통 이관 및 원본 복구 기능 |
| **파일 공유** | 내부 사용자 대상 조회/수정 권한 분리 및 사외 협력업체 전용 만료 링크 제어 메커니즘 |
| **버전 관리** | 동일 파일 재업로드 시 버전 자동 증가(V1->V2), 과거 이력 조회 및 특정 구버전 복원/다운로드 |
| **보안 기능** | 비인가 사용자의 URL 직접 접근(Deep Linking) 차단 및 데이터 전송 구간 HTTPS(TLS 1.3) 암호화 패킷 검증 |
| **성능 및 신뢰성** | 100MB 이하 파일 전송 3초 이내 보장, Quota 초과 시 제어, 동시 수정 시 낙관적 락 트랜잭션 원자성 |

## 2.2 테스트 항목 및 통과 기준

### 2.2.1 기능별 테스트 항목 및 통과 기준
| 기능별 테스트 항목 | 통과 기준 |
| :--- | :--- |
| **회원가입 기능** | 올바른 이메일 포맷 및 비밀번호 규격 입력 시 가입에 성공하고 중복 계정은 차단된다. |
| **로그인 기능** | DB에 저장된 올바른 계정 정보 매칭 시 인증에 성공하며 세션을 발급받는다. |
| **업로드 기능** | 다양한 포맷의 파일이 실제 지정 스토리지 경로에 정상 저장되고 메타데이터가 기록된다. |
| **다운로드 기능** | 파일이 깨짐 없이 원본 그대로 사용자 로컬 디스크 장치로 저장된다. |
| **검색 기능** | 단순 텍스트 매칭 검색 및 날짜+작성자+유형 등의 다중 필터링 조합 결과가 정확하게 출력된다. |
| **공유 기능** | 지정된 사용자에게 설정된 권한(조회/수정/댓글)에 맞춰 파일 접근 한도가 다르게 제어된다. |
| **버전 관리 기능** | 파일 수정 업로드 시 구버전이 이력 파일로 백업되며 필요시 구버전으로의 완벽한 복원이 지원된다. |

### 2.2.2 비기능별 테스트 항목 및 통과 기준
| 비기능 테스트 항목 | 통과 기준 |
| :--- | :--- |
| **성능 테스트** | 100MB 이하 표준 파일의 업로드 및 다운로드 전송 완료 시간이 3초 이내여야 한다. |
| **검색 테스트** | 다중 복합 검색 필터 적용 시 인덱싱을 통해 검색 결과 셋을 2초 이내에 반환해야 한다. |
| **보안 테스트** | 인증을 거치지 않은 비인가 접근(세션 무효) 요청에 대해 403 Forbidden 오류로 원천 차단해야 한다. |
| **신뢰성 테스트** | 동시 수정 충돌 시 낙관적 락에 의해 선행 작업만 성공하고 후행 작업은 안전한 예외 경고를 띄워야 한다. |

# 3. 테스트 케이스

## 3.1 테스트 케이스 선정
테스트 케이스는 요구사항 정의서의 기능 요구사항(FR)과 비기능 품질 목표(NFR)를 정밀 추적할 수 있도록 설계되었다. 정상 입력 데이터뿐만 아니라 경계값 분석(Boundary Value Analysis) 및 오류 예측 기법을 적용하여 필수 항목 누락, 비정상 포맷, 할당량 초과, 동시 트랜잭션 발생 등 예외적인 임계 상황에서 시스템의 대처와 복구 신뢰성을 다각도로 검증할 수 있도록 선정하였다.

---

## 3.2 테스트 케이스 유형
* **문자열 입력 유효성 테스트** (이메일 정규식 패턴 및 특수문자 차단 규격 검증)
* **사용자 기능 및 권한 제어 테스트** (세션 인증 및 권한 레벨별 수정 제한 검증)
* **파일 처리 및 버전 트랜잭션 테스트** (업/다운로드, 휴지통 이관, 히스토리 이력 복원 검증)
* **임계 성능 속도 및 사용성 테스트** (3초 이내 타임아웃 측정, 3-Click 이내 UI 뎁스 진단)
* **보안 암호화 및 신뢰성 테스트** (HTTPS 프로토콜 전송 구간 암호화 패킷 분석 및 동시성 락 검증)

# 4. 테스트 예외사항

## 4.1 중단 기준과 재개 조건

| 중단 기준 (Suspension Criteria) | 재개 조건 (Resumption Criteria) |
| :--- | :--- |
| **네트워크 단절 및 빌드 서버 다운**<br>- 인프라 장애 또는 라즈베리파이 테스트 서버의 물리적/논리적 끊김으로 백엔드 API에 접근이 불가능한 상태 | 네트워크 하드웨어 인프라 복구 확인 및 API 서버 헬스체크 엔드포인트 정상 응답(HTTP 200 OK) 수신 시 테스트 재개 |
| **스토리지 풀(Disk Full)로 인한 파일 시스템 마비**<br>- 대용량 파일 반복 업로드 테스트 도중 가용 저장 영역이 100%에 도달하여 입출력 쓰기 예외 에러가 나는 경우 | 휴지통 비우기 및 테스트용 임시 디렉토리 정제 자동화 스크립트 구동을 통해 가용 영역 최소 5GB 이상 확보 후 재개 |
| **인증 토큰 / 세션 컴포넌트 크래시**<br>- 보안 프로토콜 및 다중 공유 테스트 중 세션 관리 DB 오류로 인해 모든 로그인 토큰이 유실 및 비정상 파괴되는 상태 | 세션 저장소(Redis/메모리) 상태 리셋 및 테스트 자동화 스크립트 전용 관리자 토큰 재발급 프로세스 확인 후 재개 |
| **심각도 상(Blocker) 레벨의 결함 발견**<br>- 메타데이터 저장 원자성 결여로 파일 업로드 성공 후 리스트 검색 및 세부 조회가 완전히 마비되는 치명적 버그 식별 시 | 테스트 진행을 즉각 중단하고 개발 파트에 버그 리포팅 후, 수정 빌드가 CI/CD 배포 파이프라인을 통과한 것을 확인 시 재개 |
